# models/

**再配布できる重みだけをコミットする。** `.gitignore` はこのディレクトリを丸ごと塞いだ
うえで、配布してよいファイルだけを名前で開けている。ワイルドカードにしないのは、
次に置いた重みが黙って配布経路へ混ざらないようにするため。

## 配布している重み

`fuseki_degct_b3_iter1177.onnx` — 布石専用ネット（`fuseki6x64` / 1.98MB）。
方策の出力は648次元で、**価値ヘッドを持たない**（勝率の採点は41手目以降のやねうら王が
受け持つ）。ブラウザ側（`src/policy.js`）はこの次元と `outputNames` を見て、ラベル空間と
価値ヘッドの有無を自分で判定する。

乱数初期化から**1,177イテレーション**回したもの。昇格ゲート（候補とアンカーの配置だけを
入れ替えた実対局。41手目以降は両者ともやねうら王が200kノードで指す）に繰り返し合格しており、
最後の合格は iter1177 の +2.3σ（勝率54.1%、800局）。

ゲートは毎回「直前の昇格モデル」が相手なので、**σは足し算できない**
（勝率は推移的ではない）。積み上げ量は鎖からは言えないので、直接測った。
前に配っていた `iter538` と1,600局指させると **62.6% ± 1.2%（1000勝598敗2分、10.5σ、+89 Elo）**
で、この置き換えぶんの強さは鎖ではなく直接の対局で裏が取れている。

この重みは **GCT由来のパラメータを含まない**。乱数初期化した重み（`rand6x64.npz`）から
出発し、やねうら王の探索結果だけを教師信号にして自己対局で学習したものだからである。
学習の起動コマンドには GCT 派生の重みを指す引数が無い。学習と検証（ONNX書き出しの
数値パリティ、方策パリティ、ブラウザ経路のスモーク）の記録は、非公開の開発リポジトリの
`docs/degct_plan.md` にある。

## 布石フェーズの評価値（`value_mid_iter1400_t40.onnx`）

`src/value.js` が読む価値ネット（6x64 / 597,457パラメータ / 2.42MB）。
入力は方策とまったく同じ `input1` 62面 + `input2` 59面で、出力 `output_value` は
**手番側から見た勝率の logit** 1本だけ。`src/value.js` が sigmoid を掛け、手番で
先手視点へ直す。

**なぜ別のネットが要るのか。** 布石中の局面はやねうら王に渡せない。SFEN が作れない
（布石フェーズに `Position` が無い）だけでなく、玉が相手の利きに当たっている局面が
普通に出る——通常将棋の指し手生成は「相手玉が取れる局面は非合法」を前提に組まれて
いるので、渡すのは未定義動作である。

教師は**昇格ゲートが残した実対局の勝敗そのもの**（iter1001〜1399 の47本・37,523局から
450,276状態）。新しい対局は取っていない。検証は **iter1400以降の 76,632状態**で、
学習に一切入っていない世代だけを使った。

| 手番 t | AUC |
|---|---|
| 2–5 | 0.61 |
| 10–13 | 0.63 |
| 18–21 | 0.68 |
| 26–29 | 0.73 |
| 34–39 | 0.76 |

**序盤はほとんど当たらない。** コイン投げ（0.50）は超えるが、5手目の数字を優劣として
読んではいけない。画面では「見立て」と呼び、`engine_fuseki_value` に
「序盤は当てにならない」と添えてある。

**40手目（t=40）を教師に含めてある。** 40手打ち終えた局面は持ち駒が全部消えて
`input2` が全ゼロになる唯一の手番で、外して学習すると分布外になる。実際、外した版は
順位付け（AUC 0.669）は保っていたのに**勝率の水準が 0.15 ずれた**（V平均 0.323 に対し
実際の先手勝率 0.474）。含めた版では平均 0.466 で、**41手目のやねうら王との段差は
−0.007** に収まっている。だから評価グラフは布石と通常を同じ目盛りで繋いでよい。

この重みも **GCT由来のパラメータを含まない**。`ValueNet`（開発リポジトリの
`scripts/fuseki_value_net.py`）を乱数初期化から学習しただけで、事前学習済みの幹を
使っていない。教師は実対局の勝敗（0/1）だけで、GCT 由来の評価値は一切通っていない。

## 天秤将棋の価値表

`king_pairs_iter1177_games.json` — 天秤将棋（ホームで選ぶ）で、両玉を置くときと
先後を選ぶときにAIが引く表。先手玉と後手玉のマスの組（36×36 = 1,296組）ごとに
「両玉をそこに置き、3手目以降を上の布石ネットが置き、41手目からやねうら王が指したときの
先手勝率」を持つ。エンジンはこの表を引くだけで、探索はしない（`src/kings.js`）。

**値の出どころが2種類ある。**

| | 出どころ | 何組 |
|---|---|---|
| 帯の48組（置く役が引く） | **実対局の勝敗**。1組あたり634〜658局 | 48 |
| それ以外 | 41手目のロールアウト採点（1組128本） | 1,248 |

帯だけを実対局に置き換えてある。人が好きなマスに置いたときも選ぶ役が答えられるよう、
測っていない組はロールアウト由来の値（`v_rollout` に元の値、`src` に出どころ）を残す。

**なぜ置き換えたか。** ロールアウト由来のVは、1,296組から釣り合う帯を見つける仕事は
できている（広めの120候補で corr(表V, 実測) = +0.57）。しかし帯の中では範囲制限で
相関が潰れ、「どちらの側が良い組か」を当てられない。選ぶ役の規則は帯の中で使うので、
そこだけ実測に替えた。

選別と測定は別の標本で取る。第1段（120組 × 248局）で候補を絞り、第2段（64組 × 397局）を
新しい対局で取った。同じ標本で選んで同じ標本で測ると、勝者の呪いで実際より釣り合って
見える（第1段の見かけ 49.3% が第2段では 48.3%、戻り −1.0pt）。

効き目は、選別にも測定にも使っていない対局で確かめた。**最善を尽くす選ぶ役に対して**:

| 表 | 先手勝率 | 最善応答の取り分 |
|---|---|---|
| ロールアウト由来V（較正済み・旧） | 45.9% ± 0.9 | 53.4% ± 1.0 |
| **実対局のV（本表）** | **48.2% ± 0.9** | **50.4% ± 0.9** |

各3,200局、差 +3.0pt ± 1.4 = 2.2σ。**「置く役の勝率」で判断してはいけない**——
あれは選ぶ役の規則の出来と混ざっており、規則が下手なほど釣り合って見える。

その前段として、評価値から勝率への換算も実測で較正してある。41手目の評価値と、
そこから最後まで指した勝敗を4,765局ぶん突き合わせると、勝率 = sigmoid((cp − 34) / 435)
が最も当たった（従来は cp/600、41手目が互角なら勝率50%という前提）。ずれの中身は
「手番のぶんを評価値が多めに見ている」で、41手目の手番（先手）に 34cp の下駄が乗っていた。
ロールアウトの温度も、サイトのレベル5（T=0.4）に合わせてある。較正だけで
最善応答の取り分は 58.0% → 55.1% に下がり、実測への置き換えでさらに 50.4% になった。

置く役が引く組は `src/kings.js` の `POOL_SIZE`（48組）で決まる。以前は
`|V − 0.5| <= band_floor` だけで絞っていたが、帯の幅がその表の測定誤差で決まるため、
同じ規則で 10組にも 23組にもなってしまう。組数を固定して、世代によらず同じ広さにした。
広さも実対局で決めた（10 / 32 / 48 組で最善応答の取り分 55.1 / 55.5 / 53.8%。差は
1σ前後で有意ではないが、広げて崩れる証拠が無かったので多様性の大きい48組を採った）。

41手目以降を指すエンジンは、測定の途中で水匠5から Háo（同じ halfkp_256x2-32-32、
GPL-3.0）へ替えた。上の表の数字はすべて Háo で取り直したもので、水匠5の値とは混ぜない。

表は布石ネットに従属するので、**重みと世代を対で差し替える**。`src/kings.js` は
ファイル名の世代（`iterN`）を突き合わせ、ずれていれば天秤将棋だけを閉じる。
中身は上の重みとやねうら王の探索結果だけから作られており、GCT由来の値は含まない。

## 置いてよいが、コミットしてはいけない重み

`fuseki_rollout_iter38.onnx` は
[dlshogi with GCT (WCSC31)](https://github.com/TadaoYamaoka/DeepLearningShogi/releases/tag/wcwc31)
の公開モデルを初期値として学習した派生物で、**再配布の明文の許諾が無い**。手元の比較には
置いてよい（私的利用）が、コミットしてはいけない。当てるときは出力先を分ける。

```bash
node build.mjs                                            # dist/ に公開重みが入る
node build.mjs --model models/fuseki_rollout_iter38.onnx  # dist-local/ に出る。配ってはいけない
```

`node build.mjs`（引数なし）が触るのは公開重みだけなので、配布経路（`dist/`）に
再配布できない重みが乗ることはない。
